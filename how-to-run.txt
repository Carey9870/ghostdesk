path: how-to-run.txt
purpose: Plain-language guide: how GhostDesk reaches customers, how to run and test it on your Linux machine, and how to publish installers so people can install it from the landing page.

======================================================================
1. THE BIG PICTURE (read this first)
======================================================================

What your CUSTOMER does:
  1. Visits your landing page (the website).
  2. Pays for a plan -> receives a license key.
  3. Clicks "Download for Windows / macOS / Linux" and installs the app like any
     other program. After that GhostDesk is a normal app on their computer.
  4. Opens it, pastes the license key, creates a pattern + passphrase. Done.
  Their files live only on their computer, encrypted. They never use the website again,
  except to cancel or update their card.

What YOU run (two things):
  A) THE APP (apps/desktop)    - the program customers install. You build installers for it.
  B) THE WEBSITE (apps/web)    - the landing page, payments, and the small server the app
                                 asks "is this license key paid?". It must be online 24/7
                                 (host it on Vercel, a VPS, etc.). It stores NO customer files.
  packages/shared              - code both use. You never run it by itself.

Why the website is still needed even though the product is an app:
  the landing page, taking payments, handing out license keys and checking that a
  subscription is still paid all need a server. The app talks to it only for that.

2. TRY IT ON YOUR LINUX MACHINE (you already have Node, pnpm and Rust)
======================================================================

Step 1: install the Linux libraries Tauri needs (one time).
  Debian / Ubuntu:
    sudo apt update
    sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
  Fedora:
    sudo dnf install webkit2gtk4.1-devel openssl-devel curl wget file libxdo-devel libappindicator-gtk3-devel librsvg2-devel
    sudo dnf group install "c-development"
  Arch:
    sudo pacman -S webkit2gtk-4.1 base-devel curl wget file openssl xdotool libappindicator-gtk3 librsvg

Step 2: a PostgreSQL database for the website (pick one).
  Docker:
    docker run -d --name ghostdesk-db -e POSTGRES_PASSWORD=ghost -e POSTGRES_DB=ghostdesk -p 5432:5432 postgres:16
    -> DATABASE_URL=postgresql://postgres:ghost@localhost:5432/ghostdesk
  or a free hosted database (Neon, Supabase) and use its connection string.

Step 3: install the project.
  unzip ghostdesk.zip
  cd ghostdesk
  pnpm install

Step 4: create the license keys (these sign and verify licenses).
  pnpm keys
  It prints LICENSE_SIGNING_KEY=...  and  GHOSTDESK_LICENSE_PUBLIC_KEY=...
  Keep both; you need them in the next steps.

Step 5: configure the website.
  cp apps/web/.env.example apps/web/.env
  Open apps/web/.env and fill it in. For a first LOCAL test (no real payments) dummy
  values are fine for these, only DATABASE_URL and LICENSE_SIGNING_KEY must be real:
    DATABASE_URL=postgresql://postgres:ghost@localhost:5432/ghostdesk
    LICENSE_SIGNING_KEY=<from pnpm keys>
    PAYSTACK_SECRET_KEY=sk_test_dummydummy
    PAYSTACK_PLAN_WEEKLY=PLN_dummy1
    PAYSTACK_PLAN_YEARLY=PLN_dummy2
    RESEND_API_KEY=re_dummydummy
    MAIL_FROM=GhostDesk <hello@example.com>
    NEXT_PUBLIC_SITE_URL=http://localhost:3000
    NEXT_PUBLIC_COMPANY_NAME=GhostDesk
    NEXT_PUBLIC_SUPPORT_EMAIL=support@example.com
    GITHUB_REPO=your-github-user/ghostdesk
  (Real payments need real Paystack and Resend values: see section 4.)

Step 6: create the database tables and start the website.
  pnpm --filter @ghostdesk/web db:push
  pnpm dev:web
  Open http://localhost:3000 : that is your landing page.

Step 7: give yourself a test license (skips paying).
  In a second terminal:  pnpm --filter @ghostdesk/web exec prisma studio
  Open the "License" table and add a row:
    key          GD-TEST-ABCD-2345-WXYZ    (shape GD-XXXX-XXXX-XXXX-XXXX; letters A-Z
                                            except I and O, digits 2-9 only)
    email        you@example.com
    plan         weekly
    customerCode test
    status       ACTIVE
    accessUntil  any future date
  (Use letters/digits from that allowed set, e.g. GD-ABCD-EFGH-2345-JKLM.)

Step 8: run the desktop app.
  Create the file apps/desktop/.env with one line:
    VITE_WEB_URL=http://localhost:3000
  In a THIRD terminal, in the project folder:
    export GHOSTDESK_API_BASE=http://localhost:3000
    export GHOSTDESK_LICENSE_PUBLIC_KEY=<value from pnpm keys>
    (cd apps/desktop && pnpm tauri icon app-icon.svg)
    pnpm dev:desktop
  The first run compiles Rust and takes several minutes. A window opens.
  The app opens without a license (one free file). Draw a pattern, choose a passphrase and SAVE the
  recovery key. Add files, try Security > Backup / Decoy vault, try the auto-lock.

Linux note: the OS-wide panic shortcut (Ctrl+Shift+L from any app) does not work on
Wayland. The pink Panic lock button and Ctrl+Shift+L inside the app always work.

Tests:  cd apps/desktop/src-tauri && cargo test      and      pnpm typecheck

Build a Linux installer on your machine:
  pnpm --filter @ghostdesk/desktop tauri build
  Results are in apps/desktop/src-tauri/target/release/bundle/ (deb, rpm, appimage).
  Use the same exported GHOSTDESK_* variables, but with your REAL website address.
  You can only build the Linux installer on Linux. Windows and macOS need section 3.

======================================================================
2b. SEE THE DOWNLOAD BUTTON WORK ON YOUR MACHINE (Linux installer)
======================================================================

  1. In the terminal where you exported GHOSTDESK_API_BASE and GHOSTDESK_LICENSE_PUBLIC_KEY:
       pnpm --filter @ghostdesk/desktop tauri build
     (10-20 minutes the first time.) It makes .deb and .rpm files, and an .AppImage
     if your system supports it, in apps/desktop/src-tauri/target/release/bundle/.
  2. Copy them to the website:   pnpm installers:local
  3. Open http://localhost:3000 and click "Download for Linux". The file downloads.
  4. Install it like any program, for example:
       sudo apt install ./apps/web/public/downloads/GhostDesk_1.0.0_amd64.deb
     then open "GhostDesk" from your applications menu.
  Windows and macOS installers cannot be built on Linux: use section 3.

======================================================================
3. PUBLISH INSTALLERS SO PEOPLE CAN INSTALL FROM THE LANDING PAGE
======================================================================

You cannot build Windows or macOS installers on Linux. GitHub does it for free:

  1. Create a public GitHub repository and push the project to it (commit pnpm-lock.yaml
     and pnpm-workspace.yaml too; never commit .env files, .gitignore already skips them).
     Commands: git init && git add . && git commit -m "GhostDesk" && git branch -M main &&
     git remote add origin https://github.com/YOU/ghostdesk.git && git push -u origin main
  2. Repository > Settings > Secrets and variables > Actions > New repository secret.
     Add these three (use your REAL, public website address):
       GHOSTDESK_API_BASE            https://your-domain.com
       VITE_WEB_URL                  https://your-domain.com
       GHOSTDESK_LICENSE_PUBLIC_KEY  the value printed by pnpm keys
  3. Create a release by pushing a version tag:
       git tag v1.0.0
       git push origin v1.0.0
     The workflow in .github/workflows/release.yml builds Windows (.exe/.msi),
     macOS (.dmg) and Linux (.AppImage/.deb/.rpm) and attaches them to a release.
  4. Set GITHUB_REPO=your-github-user/ghostdesk in the website settings.
     The landing page's "Download for ..." buttons then find the newest release
     automatically, so shipping an update is just pushing a new tag.

Before charging money, sign the installers (Windows code-signing certificate, Apple
Developer account with notarization). Unsigned installers show scary warnings.

======================================================================
4. GO LIVE
======================================================================

  - Host the website (Vercel, Railway, Fly.io or a VPS) with a production Postgres
    database. Add every variable from apps/web/.env to the host and run
    pnpm --filter @ghostdesk/web db:push once against the production database.
  - Paystack: switch to LIVE keys, put the live secret key in PAYSTACK_SECRET_KEY, run
    pnpm plans (it prints the real plan codes for USD 5 weekly / USD 20 yearly), and
    paste them into PAYSTACK_PLAN_WEEKLY / PAYSTACK_PLAN_YEARLY. In the Paystack
    dashboard set the webhook to https://your-domain.com/api/webhooks/paystack and copy
    its signing secret into PAYSTACK_WEBHOOK_SECRET. Ask Paystack to enable USD if needed.
  - Resend: verify your sending domain and use it in MAIL_FROM.
  - Fill NEXT_PUBLIC_COMPANY_NAME and NEXT_PUBLIC_SUPPORT_EMAIL, and have a lawyer
    review /privacy and /terms.

======================================================================
5. WHAT EACH PART OF THE PROJECT IS FOR
======================================================================

apps/desktop (the product)
  src-tauri/  Rust core: encryption, pattern + passphrase unlock, decoy vault, backups,
              recovery key, file import/export, unlock throttle, license check.
  src/        The screens (lock screen, vault, sidebar, viewer, auto-lock dialog).
              It never touches keys; it asks the Rust core through src/lib/ipc.ts.
  tauri.conf.json5   window, security policy and permissions.
apps/web (the business side)
  landing page, pricing dialog, Download buttons, Privacy and Terms pages;
  /api/checkout (start a payment), /api/webhooks/paystack (payment events),
  /api/license/check (the app asks if a key is paid), /api/license/manage (update card
  or cancel), /download/[os] (sends the visitor to the newest installer);
  prisma/schema.prisma = database tables (licenses, devices, payments). No files.
packages/shared   passphrase rules, plan prices and the pattern grid, used by both.
.github/workflows/release.yml   builds the Windows/macOS/Linux installers.
scripts (apps/web/scripts)      generate-keys.ts and create-plans.ts, run once each.

======================================================================
6. COMMON PROBLEMS
======================================================================

"This build has no license public key configured" / "no license server configured"
    You did not export GHOSTDESK_LICENSE_PUBLIC_KEY / GHOSTDESK_API_BASE in the SAME
    terminal before pnpm dev:desktop. Export them, delete apps/desktop/src-tauri/target
    (or run: touch apps/desktop/src-tauri/build.rs) and run again.
"Couldn't reach the license server"   The website (pnpm dev:web) is not running.
Key rejected                          Check the exact key and the License row in Prisma Studio.
Missing icons error on build          cd apps/desktop && pnpm tauri icon app-icon.svg
Old vault will not open               Delete the app data folder and start fresh:
                                      Linux ~/.local/share/app.ghostdesk.desktop
Passphrase rejected                   14-17 characters, a lowercase letter, 2+ capitals, a
                                      number, a symbol (like ! or #) and a space.
Installer download says "isn't published yet"   Check GITHUB_REPO and that the release is
                                      public and finished building.

Important: this code was written without being compiled in its authoring environment, so
the first build may reveal small type or version errors to fix.
